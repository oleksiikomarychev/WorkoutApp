# Ошибка применения плана с ложным статусом SUCCESS

- Статус: verified
- Область: plans-service, async применение
- Класс: async-state
- Обнаружен и проверен: 2026-11-12
- Связи: AP-4, GAP-9, `plan-operation-contracts`

## Условие и влияние

Запрос для несуществующего плана принимался в очередь. Worker ловил ValueError
и возвращал словарь `ok=false`, поэтому Celery отмечал задачу SUCCESS. Flutter
проверял только FAILURE и мог сообщить об успешном применении.

## Воспроизведение и исправление

Синтетический план ID 999 отсутствует в изолированной БД. Async HTTP-запрос через
настоящий gateway создаёт задачу, затем клиент опрашивает её статус.
До исправления тест получил SUCCESS с вложенным `ok=false`; после исправления —
FAILURE. Доменная ошибка больше не превращается в успешный результат задачи и
не повторяется автоматически.

Регрессия:
`tests/integration/test_plan_operation_pipeline.py::test_async_application_domain_error_is_failure_not_success`.
Запуск из корня: `python3 scripts/test_plan_contracts.py`. Инфраструктура: временные
PostgreSQL 16 и Redis 7, настоящие HTTP и Celery. Проверены исходное и исправленное
поведение в рабочем дереве 2026-11-12; пользовательские данные не используются.

# Несогласованный контракт замены плана между сервером и Flutter

- Статус: fixed
- Область: plans-service и Flutter `PlanApi` / `CalendarPlanDetail`
- Класс: compatibility / existing-state
- Обнаружен: 2026-11-12, замечание владельца проекта
- Связи: AP-2, задача 1.2 `plan-operation-contracts`

## Условие и влияние

У пользователя уже есть активный план. Backend требует `replace_active=true`,
а прежний Flutter не передавал признак. Вместо ранее доступной замены клиент
получал 409. Первое применение без активного плана не затрагивалось.
Проверка backend без запуска клиентского сценария не выявила несовместимость.

## Исправление

Flutter предлагает подтверждение после 409. При подтверждении повторяет запрос
с флагом; при отмене не делает повтор. Другие ошибки не вызывают диалог и retry.
Параметр добавлен в sync и async методы `PlanApi`; экран использует async-путь.

## Проверка и ограничения

В соседнем `workoutapp_clients/flutter_app` добавлен
`test/calendar_plan_apply_confirmation_test.dart`: первое применение, подтверждение,
отмена, ошибка сервера, ошибка после подтверждения, параметры sync/async API.

До исправления: отсутствие флага подтверждено чтением прежнего вызова; полный UI
тест на исходном экране не выполнялся, поэтому статус `verified` не присваивается.
После исправления: widget/API тесты прошли 2026-11-12 в рабочем дереве. Полный
GUI-поток и production-релиз не выполнялись; backend и клиент выпускаются совместно.

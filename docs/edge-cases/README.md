# Edge cases

Записываем дефекты на пограничных значениях или особых сочетаниях состояний:
пустые/устаревшие данные, повтор запроса, гонка, граница даты, частичный сбой,
необычная комбинация статусов. Редкость не обязательна. Обычная опечатка или любой
баг без такого условия не требуют записи.

Имя: `EC-YYYYMMDD-short-slug.md`; ID совпадает с именем без расширения.
Перед созданием ищем похожий случай. Используем [шаблон](TEMPLATE.md), ссылки на
реальные тесты и синтетические данные. Запись не заменяет регрессионный тест.

- `recorded` — описан, воспроизведение не подтверждено;
- `reproduced` — исходный дефект воспроизведён;
- `fixed` — исправление есть, повторная проверка не завершена;
- `verified` — проверка выявляет дефект до исправления и проходит после;
- `obsolete` — сценарий исчез; указать причину и ссылку на изменение.

При повторной регрессии вернуть `reproduced`, дополнить историю. Если исходную версию
нельзя запустить, записать это и не выставлять `verified`. При работе с областью
агент повторяет релевантные тесты и обновляет дату/команду/результат; при невозможности
выполнить проверку указывает причину.

Записи регрессий находятся рядом с этим README (файлы `EC-*.md`). Наличие теста
само по себе не доказывает историю бага: каждая запись указывает, был ли тест
запущен на исходной версии и на исправлении.

# Потеря параметров переноса при постановке задачи

- Статус: verified
- Область: workouts-service, async перенос расписания
- Класс: partial-state / async-command
- Обнаружен и проверен: 2026-11-12
- Связи: задача 3.3 change `plan-operation-contracts`

## Условие и влияние

HTTP-запрос `shift-schedule-async` содержал `mode=preview` и ограничение `to_date`.
Worker восстанавливал только часть команды, теряя оба поля; preview превращался
в apply и изменял даты за пределами запрошенного диапазона.

## Воспроизведение

Синтетические тренировки на 15, 16 и 17 ноября. Preview ограничен 15 ноября,
сдвиг — три дня. Ожидается неизменность всех дат. До исправления тест получил
`mode=apply`, лог показал изменение двух тренировок.

## Исправление и проверка

Endpoint передаёт всю сериализованную команду. Worker принимает её целиком;
старые уже поставленные задачи со скалярными полями остаются совместимыми.
Регрессия: `tests/integration/test_plan_operation_pipeline.py::test_async_mass_edit_and_shift_preserve_command_filters`.
Тест падал до исправления и прошёл после на PostgreSQL 16 + Redis 7 + реальном Celery.

Тот же тест сначала выявил отдельный дефект постановки: endpoint не передавал
обязательный `celery_app` в `enqueue_task` и отвечал 500. Это исправлено для
массовой правки и переноса до проверки передачи команды.

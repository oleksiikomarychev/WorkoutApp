- Заменяет / заменено: —

## Контекст

Преобразования и проверки распределены между сервисами и потребителями. Чтение
схем показывает разные ограничения создания/обновления силового максимума и
автоматическое округление дробного числа повторений в RPE. Эти наблюдения сами
по себе не определяют согласованную политику и не являются воспроизведённым багом.

## Решение

1. **У данных определён смысл.** Для величины известны единица, допустимые значения,
   точность и округление. Отсутствие, неизвестное значение и ноль различаются.
   Преобразования и подстановка значения по умолчанию следуют явному правилу.
2. **Данные проверяются согласованно.** Создание, редактирование, импорт, API и AI
   применяют одну доменную политику. Различия объясняются смыслом операции:
   например, пропущенное поле при частичном обновлении означает сохранение прежнего.
3. **Известны источник и роль данных.** Различаются исходная сущность, экземпляр,
   исторический снимок и вычисленный результат. Кеш или копия не становятся
   независимым источником истины. При изменении исходника явно определяются
   зависимые данные для пересчёта и данные, которые сохраняются.

Конкретные диапазоны RPE, единицы и шаг округления веса, правила дозировок и
обновления исторических снимков задаются внутри соответствующих capabilities
и changes. Решение не предписывает пересчитывать всю историю или сохранять любой
снимок неизменным. Единый числовой диапазон, механизм версионирования или одна
схема хранения для всех сервисов не назначаются.

## Альтернативы и причины

Независимые правила в каждом транспорте создают неоднозначность смысла одной
величины. Общая основа связывает проверки и преобразования, сохраняя различия
доменов и операций; отдельный requirement для каждого числового примера не нужен.

## Последствия

DATA принят как целевой контракт. Для затронутой области change определяет смысл
полей, источник/роль данных и влияние правки исходника, затем выбирает проверки.
Полное соответствие существующих сервисов не подтверждено. Runtime, миграции
и основные specs этим шагом не меняются; пауза изменений сервисов сохраняется.

## Проверка и пересмотр

Основное свойство: при передаче, преобразовании и сохранении данные сохраняют
согласованный смысл. Применимые проверки охватывают единицы и точность, границы,
отсутствие/неизвестное/ноль, одинаковое предоставленное значение в разных путях
ввода с учётом смысла операции, а также пересчёт или сохранение зависимых данных.
Обратимость, монотонность и общая точность для всех формул не предполагаются.

В этом шаге проверяются документы и конфигурация OpenSpec. Тесты сервисов,
вычисления, миграции и подключения к БД не запускались. Реальные доказательства
соответствия фиксируются отдельно в реализующих changes.

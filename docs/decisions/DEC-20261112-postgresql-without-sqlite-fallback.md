## Контекст

В supplements/models.py при отсутствии URL и при исключении подключения выбирается
`sqlite:///:memory:`. Это установлено чтением кода; сбой и потеря данных не
воспроизводились. Происхождение fallback как отладочного решения — предположение
владельца, не подтверждённая история изменения.

По сообщению владельца сейчас доступен только локальный PostgreSQL; Neon и VPS
недоступны. Это ограничение текущего окружения, а не причина менять движок БД.

## Решение

Рабочие данные приложения хранятся в PostgreSQL. SQLite, включая in-memory,
и автоматическая подмена PostgreSQL таким хранилищем не допускаются, в том числе
для локального запуска приложения. Отсутствие конфигурации или отказ подключения
не разрешают подтверждать запись в альтернативную временную БД.

Конкретная реакция запуска/API на отказ, readiness и обязательность отдельных
capabilities определяются при реализации ограниченного change. Настоящее решение
не утверждает, что код уже соответствует правилу. Существующие SQLite test fixtures
не считаются согласованным исключением; их пересмотр не выполнен этим шагом.

## Альтернативы и причины

Сохранение неявного fallback отклонено прямым указанием владельца. Недоступность
удалённого PostgreSQL не является основанием использовать SQLite.

## Последствия

OBS-01 теперь является расхождением с принятым решением. Удаление fallback,
проверки отказа и выбор локальной тестовой БД остаются будущей реализацией.
Для текущей работы с документацией подключение к БД не требуется.

## Проверка и пересмотр

В будущем change проверить отсутствие SQLite при пустом URL и ошибке подключения,
а также работу с изолированным PostgreSQL. Здесь выполнена только фиксация решения;
runtime, подключения к БД и тесты сервисов не запускались.

# Решения и договорённости

Одна запись — одно содержательное решение: архитектурный выбор, продуктовая семантика
или устойчивое правило разработки. Для мелких деталей достаточно design/tasks change.
Имя: `DEC-YYYYMMDD-short-slug.md`. Используем [шаблон](TEMPLATE.md).
Храним вывод и причины, а не стенограмму.

- `proposed` — предложено, не является правилом проекта;
- `accepted` — согласовано, указаны кем, когда и на каком основании;
- `rejected` — отклонено с причиной;
- `superseded` — заменено, обязательна ссылка на новое решение.

Основанием может быть прямое указание владельца в задаче, ответ в обсуждении или
принятый PR. Если ссылки на чат нет, указываем дату и точную короткую формулировку.
Не требуем повторного одобрения принятого решения. Молчание, гипотеза агента,
существующий код и выбор темы не равны согласию с деталями.

При смене курса создаём новое решение и связываем записи; не переписываем историю.
При конфликте со spec явно разбираем расхождение.

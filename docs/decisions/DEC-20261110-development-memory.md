# DEC-20261110-development-memory: сохранять edge cases и договорённости

- Статус: accepted
- Дата: 2026-11-10
- Область: процесс разработки
- Кем и когда согласовано: владелец проекта, запрос в чате 2026-11-10
- Основание: «при багах которые можно классифицировать как эдж кейсы записывать их
  и после воиспроизводить»; «артефакты пришедших консенсусов».
- Связи: [процесс](../development/README.md), [edge cases](../edge-cases/README.md)

## Решение

Сохранять пограничные дефекты для последующего воспроизведения и содержательные
решения, к которым пришли в разработке. Новые области спецификаций предлагать
владельцу проекта для выбора.

В ответе 2026-11-10 владелец выбрал первой областью «Планы и тренировки:
применение плана, переносы, массовые правки». Это приоритет обсуждения,
а не согласование поведения операций.

## Причины и границы

Нужно переносить опыт между задачами и не терять причины договорённостей.
Конкретные пути, шаблоны и статусы — начальная реализация процесса агентом;
они не выдаются за отдельно обсуждённый архитектурный консенсус.
На момент этого решения продуктовые вопросы оставались открытыми. Позднее три правила
применения плана приняты в [отдельном решении](DEC-20261110-plan-application-rules.md).

## Последствия и пересмотр

При подходящем баге добавляем воспроизводимый случай; при договорённости — решение
с источником. Пересмотреть формат, если записи перестанут помогать воспроизведению
или начнут дублировать specs. Альтернативные форматы пока не обсуждались.

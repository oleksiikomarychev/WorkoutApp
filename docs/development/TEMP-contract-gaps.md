| GAP-1 | Обычное применение заменяло активный план вместо отказа | Исправлено: 409 без `replace_active`. Конкурентный PostgreSQL guard оставляет одну запись; HTTP-тест через gateway подтверждает отказ |
| GAP-2 | Отсутствовал явный признак замены | Исправлено: query `replace_active=true` проходит sync/async endpoint и worker. Оба HTTP-пути замены сохраняют завершённую историю |
| GAP-3 | Ошибка после сохранения первого пакета могла оставлять Workout неуспешного плана | Исправлено: rollback плана, HTTP-очистка, фоновая задача при ошибке. Стенд проверил успешный первый пакет, отказ второго, два отказа очистки и настоящий Celery retry. Начатая тренировка отделяется без потери progress |
| GAP-4 | Массовая правка могла менять завершённую тренировку без фильтра status | Исправлено: обязательное исключение по `completed_at OR status=completed`, независимо от входного фильтра. Проверено SQLite, PostgreSQL и async/Celery сценарием |
| GAP-5 | Отдельные commit и скрытые ошибки оставляли частичную массовую правку | Исправлено: единая граница commit, ошибки прерывают обход. PostgreSQL и HTTP/worker тесты подтвердили исходные веса после сбоя второй правки |
| GAP-6 | Перенос и массовая правка использовали разные признаки завершения | Исправлено: оба признака используются во всех путях переноса и правки. PostgreSQL-тест завершения во время row lock подтвердил неизменность тренировки |
| GAP-7 | Пакеты Workout видны до завершения всего применения | [Согласованное ограничение](../decisions/DEC-20261110-temporary-workout-visibility.md). При сбое не начатые удаляются; [начатые сохраняются отдельно](../decisions/DEC-20261112-preserve-started-workout-on-cleanup.md). Проверено чтение списка и HTTP-очистка |
| GAP-8 | Async перенос терял `preview`/`to_date`; mass-edit и shift не передавали Celery app при enqueue | Исправлено: полная команда передаётся worker, старый формат очереди поддержан. Тест падал с 500, затем с `apply != preview`, после исправления прошёл |
| GAP-9 | Ошибка применения внутри worker возвращала `ok=false` со статусом SUCCESS | Исправлено: доменные ошибки завершаются FAILURE, без бессмысленного retry. Тест неизвестного плана через gateway и Celery падал до исправления и прошёл после |
| GAP-10 | Старый endpoint переноса по индексу не защищал завершённые тренировки | Исправлено: тот же обязательный фильтр обоих признаков. Тест воспроизвёл изменение индекса завершённой тренировки до исправления, после изменения прошёл |

## Ограничения и отдельные последующие работы

- Production compose теперь включает worker очередей `plans.tasks` и `workouts.tasks`.
  Синтаксис проверен, доставка задач и retry проверены на изолированном стенде.
  Сборка/запуск production-образов и развёртывание не выполнялись.
- Полная потеря брокера или исчерпание восьми фоновых повторов требуют операционного
  восстановления. Введённые лог-события и пределы описаны в документе API; outbox
  для компенсаций не входит в change.
- Flutter checkout `3546430` исправлен в рабочем дереве: UI подтверждает замену
  при 409 и передаёт `replace_active=true`. API и диалог проверены 14 тестами
  вместе с существующими действиями планов. Backend и клиент требуют совместимого выпуска.
  Прежний отчёт о завершённости backend не означал совместимость старого клиента;
  эта ошибка зафиксирована в EC-20261112-client-replacement-flag.
- При чтении соседнего кода замечено отсутствие `celery_app` у enqueue импорта Hevy.
  Это отдельный поток, не исправлявшийся данным change; дефект отмечен чтением,
  тест не запускался. Нужна отдельная локальная правка с проверкой импорта.

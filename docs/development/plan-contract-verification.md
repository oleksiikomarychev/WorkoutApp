# Проверка plan-operation-contracts

Дата: 2026-11-12. Проверено рабочее дерево; коммит и развёртывание не выполнялись.

## Повторяемый запуск

Из корня репозитория с доступным Docker и подготовленным Python workspace:

```sh
python3 scripts/test_plan_contracts.py
```

Скрипт использует `uv run --no-sync`: нужны установленные зависимости workspace,
pytest, pytest-asyncio, grpcio-tools, asyncpg, uvicorn и Celery с Redis transport.
Он создаёт PostgreSQL 16 и Redis 7 с уникальными именами и случайными локальными
портами, генерирует protobuf stubs во временный каталог и удаляет контейнеры
и файлы после выполнения, включая завершение с ошибкой. Приложения не используют
`.env` для подключения к данным: все DB session factories заменены изолированными
схемами временной тестовой БД. Внешние значения пользователя/упражнений синтетические.

Результат: **44 теста прошли** — 12 интеграционных, 8 plans-service, 24 workouts-service.

## Что проверено

| Гарантия | Доказательство |
| --- | --- |
| Обычное применение не заменяет активный план | HTTP 409 через gateway; PostgreSQL-тест конкурентного guard создаёт только одну запись |
| Явная замена сохраняет историю | Оба пути через gateway, sync и async/Celery, сохраняют завершённую Workout старого плана |
| Ошибка второго пакета не даёт успешный план | Реальный HTTP generation первого пакета, внедрённый отказ второго, rollback plans DB и очистка workouts DB |
| Сбой очистки восстанавливается | Отказ inline-очистки, отказ первой Celery-попытки, настоящий retry и успешная очистка; в тесте countdown сокращён с 60 до 0 |
| Начатая тренировка сохраняется отдельно | Реальная сессия с progress, сбой следующего пакета, удаление связи без потери progress |
| Неполный HTTP 200 от генератора не считается успехом | Несоответствие числа ID ожидаемому пакету вызывает ошибку и очистку |
| Доменная ошибка async-применения не даёт ложный SUCCESS | Неизвестный план завершается FAILURE в Redis result backend и HTTP status endpoint |
| Завершённые Workout не меняются | Оба признака завершения; новый и прежний пути переноса; массовая правка |
| Завершение во время переноса защищено | PostgreSQL row lock: перенос ждёт commit завершения и исключает Workout |
| Массовая правка откатывается целиком | Ошибка второй правки после flush первой: исходные веса в новой сессии; проверены HTTP и worker |
| Async перенос не теряет команду | Preview не пишет данные; apply соблюдает `to_date`; завершённая Workout исключена |
| Очистка идемпотентна и изолирована | Повтор удаляет ноль строк; другой пользователь и его тренировка сохраняются |

Стенд поднимает настоящие HTTP-серверы gateway/plans/workouts и Celery worker с
Redis. Идентификация пользователя задана тестовым middleware; Firebase, реальные
exercise/user-max/RPE сервисы, полный Flutter экран и production-образы здесь не проверяются.
Это E2E выбранных backend-контрактов в изолированном стенде, а не прогон всего продукта.

  ограничением, см. [API и восстановление](plan-operation-api.md).

  test/calendar_plan_actions_test.dart` из `flutter_app/`: 14 тестов прошли.

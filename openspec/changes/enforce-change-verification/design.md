# Design

## Context

См. proposal. Установлен pre-commit 4.7; текущий config запускает только Ruff.
Есть изолированный Docker runner плановых контрактов и suite RPE с mocked внешними
вызовами. Другие suite могут использовать application SessionLocal при импорте.

## Goals / Non-Goals

Реальные локальные проверки при ограниченных расходах. Не добавлять Actions,
не менять БД приложения и не объявлять выборочную регрессию полным покрытием сервиса.

## Decisions

- DoD — короткая таблица в существующем verification.md/tasks.md, с точными ссылками
  на requirement/scenario, командой, результатом и ограничениями. Семантическую полноту
  проверяет итоговый review; hook не выводит её из наличия текста или зелёного pytest.
- pre-commit: быстрая валидация OpenSpec на каждом commit (включая удаления);
  pre-push: OpenSpec и объединение
  безопасных наборов по путям. Ruff остаётся на commit. Установка обоих hook типов
  через существующий pre-commit, без замены core.hooksPath.
- Один Python runner со стандартной библиотекой: явные файлы/рабочее дерево для
  ручного запуска, PRE_COMMIT_FROM_REF/TO_REF для push. Git diff без rename detection
  сохраняет удалённые пути. При отсутствии исходного ref берётся дерево новой версии.
  На автоматическом push требуются текущий HEAD и чистое дерево; тесты запускаются
  в checkout. Альтернатива — отдельный worktree на каждый push — пока избыточна.
- Начальные наборы: workflow (unittest самого gate), plan-contracts (существующий
  disposable PostgreSQL/Redis runner), rpe (изолированная генерация proto и выбранный suite).
  Plan runner задаёт application DB/Redis URL временного стенда до импорта модулей,
  включая supplements sync engine; подмены pytest sessions после импорта недостаточно.
  Изменения общих зависимостей включают оба сервисных набора. Неизвестный runtime-путь
  блокирует push с предложением добавить безопасный набор; docs не запускают весь стек.
- Карта выбора в коде runner, без второго реестра требований и без исполнения shell
  из Markdown. Полноту тестов конкретного change всё равно проверяет таблица DoD.
- Plan runner завершает все свои группы и возвращает ошибку, если хотя бы одна упала;
  это сохраняет наблюдаемость регрессий без маскировки неуспеха. Существующий
  баг сервиса не исправляется изменением критерия: ошибочный набор блокирует push.

## Risks / Trade-offs

- Hooks можно обойти/не установить → документировать; обязательный серверный gate
  отдельно, не обещать равенства hooks и CI.
- Нет безопасного runner для части сервисов → явный отказ вместо импорта неизвестной
  suite; следующий затрагивающий область change добавляет проверенный набор.
- Общие изменения дороже → запускаются оба ограниченных набора, а не весь продукт.
- Локальная ветка грязная → ручной --worktree разрешён, автоматический push ждёт commit.

## Migration Plan

Добавить config/runner/docs, проверить на синтетических временных Git repos и реальных
начальных наборах. Установить оба hooks в текущем checkout. Другие checkout используют
документированную команду установки. Откат — удалить новые local hook entries и
переустановить pre-commit; продуктовые данные и API не затронуты.

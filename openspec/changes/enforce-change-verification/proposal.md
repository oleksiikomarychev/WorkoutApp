# Proposal

## Why

Отмеченные tasks и валидные Markdown-файлы не подтверждают требования. Нужны
конкретный критерий завершения change и повторяемые выборочные проверки до push.

## What Changes

- Ввести в существующий verification/tasks отчёт связь требования, сценария,
  проверки, фактического результата и ограничений; непроверенная обязательная гарантия блокирует завершение.
- Через pre-commit валидировать OpenSpec, через pre-push запускать безопасные
  тестовые наборы по изменённым путям; GitHub Actions не добавлять.
- Показывать выбранные проверки; неизвестная runtime-область и недоступные инструменты
  завершают проверку неуспехом. Не запускать произвольные pytest suite с обычным `.env`.
- Документировать установку hooks, ручной запуск и пределы локального контроля.

## Capabilities

### New Capabilities

- `change-verification`: критерий завершения и выборочные локальные проверки изменений.

### Modified Capabilities

Нет изменений продуктовых контрактов.

## Impact

DELIVERY: AGENTS.md, OpenSpec config, docs/development, pre-commit config и scripts/tests.
Потребители — разработчик, агент и локальные hooks. Применимы EXEC (результат проверки),
READY (явный отказ при недоступном инструменте), COMPAT (потребители и hooks).
ACCESS/DATA/EVENT продукта не меняются. Основание — прямой запрос владельца в чате.
Связанные [правила процесса](../../../docs/development/README.md) и
[случай несовместимости клиента](../../../docs/edge-cases/EC-20261112-client-replacement-flag.md).

Вне объёма: исправление сервисов, перенос тестов всех сервисов на PostgreSQL,
серверный запрет обхода hooks, изменения Actions/branch protection и новый реестр требований.

# План розробки Telegram-бота WorkoutApp

Цей документ описує архітектуру, функціонал та етапи розробки полегшеної версії застосунку WorkoutApp у вигляді Telegram-бота.

## 1. Основна концепція
Бот є "lightweight" версією основного застосунку. Основна мета — надати користувачам швидкий доступ до їхніх планів тренувань, фіксації повторних максимумів (1RM) та проведення тренувань із автоматичним розрахунком робочої ваги на основі планів. 
Дані бота (моделі) повністю відповідають моделям мікросервісів для забезпечення безшовної синхронізації (експорту) даних в основний застосунок.

## 2. Функціонал, який переноситься
1. **Управління повторними максимумами (User Maxes)**
   - Перегляд поточних максимумів для вправ.
   - Додавання нових максимумів.
   - Розрахунок `true_1rm` (справжнього 1RM) на основі RPE, ваги та кількості повторень (логіка з `workout_calculation.py`).

2. **Плани тренувань (Calendar Plans)**
   - Перегляд доступних планів (CalendarPlan, Mesocycle, Microcycle).
   - Застосування плану користувачем (AppliedCalendarPlan).

3. **Проведення тренування (Workout Execution)**
   - Генерація тренування на поточний день на основі `AppliedCalendarPlan`.
   - Автоматичний розрахунок робочої ваги для підходів на основі % від `true_1rm` користувача або абсолютної нормалізації (згідно логіки застосунку).
   - Фіксація виконаних тренувань (Workout, WorkoutSession, WorkoutExercise, WorkoutSet).

4. **Експорт даних**
   - Бот генерує JSON-файл з усіма накопиченими даними (максимуми, застосовані плани, тренування) та відправляє його безпосередньо у чат.
   - Синхронізація відбувається шляхом збереження цього JSON-файлу користувачем із Telegram та його завантаження (імпорту) в основний застосунок.

## 3. Моделі даних (Тотожні до застосунку)
Для забезпечення сумісності будуть використані SQLAlchemy моделі, що повністю повторюють структуру БД мікросервісів:
- **З `user-max-service`**: `UserMax`, `UserMaxDailyAgg`.
- **З `plans-service`**: `CalendarPlan`, `AppliedCalendarPlan`, `Mesocycle`, `Microcycle`, `PlanWorkout`, `PlanExercise`, `PlanSet`.
- **З `workouts-service`**: `Workout`, `WorkoutSession`, `WorkoutExercise`, `WorkoutSet`.
- **З `exercises-service`**: `ExerciseList`.

Ідентифікатор користувача (`user_id`) у боті буде базуватися виключно на Telegram Account ID (наприклад, `tg:123456789`). Бот **не матиме** системи авторизації через акаунти основного сервера, забезпечуючи повну автономність роботи суто через Telegram.

## 4. Архітектура та Технології
- **Фреймворк**: `aiogram` (Python, асинхронний).
- **База даних**: Локальна **SQLite** з ідентичною схемою бази даних через `SQLAlchemy` (v2.0) та `Alembic` для міграцій. Це робить бота повністю автономним від основного сервера.
- **Логіка розрахунків**: Буде портована логіка класів `WorkoutCalculator` (з `plans_service` та `workouts_service`) для розрахунку `true_1rm`, інтенсивності та нормалізації мікроциклів.

## 5. Етапи реалізації

### Етап 1: Ініціалізація та База даних
- Створення структури проекту бота.
- Налаштування підключення до БД.
- Копіювання та адаптація SQLAlchemy моделей (`models.py`) з мікросервісів.
- Налаштування Alembic та створення початкової міграції.

### Етап 2: Управління Максимумами (1RM)
- Розробка меню `/maxes`.
- Логіка додавання максимуму (вибір вправи, введення ваги, повторень, RPE).
- Інтеграція `WorkoutCalculator.calculate_true_1rm` для обчислення справжнього 1RM.

### Етап 3: Робота з планами
- Меню `/plans`.
- Можливість завантажити список доступних планів.
- Створення запису `AppliedCalendarPlan` при виборі плану.

### Етап 4: Режим Тренування
- Команда `/workout` або кнопка "Почати тренування".
- Витягування `PlanWorkout` на поточний день.
- Розрахунок робочих ваг для кожного підходу: `вага = UserMax.true_1rm * (PlanSet.intensity / 100)`.
- Інтерфейс (Inline клавіатури) для відмітки виконаних підходів.
- Збереження результатів у таблиці `Workout`, `WorkoutExercise`, `WorkoutSet`.

### Етап 5: Синхронізація (Експорт)
- Команда `/export`.
- Формування JSON-файлу з новими даними (`UserMax`, `AppliedCalendarPlan`, `Workout` тощо) у форматі, тотожному до моделей застосунку.
- Відправка цього файлу безпосередньо у чат користувачу у вигляді документа (дозволяє зберегти та завантажити в основний застосунок).
